**Контекст:** после первоначальной настройки [узел](/apex/glossary#node) управляется исключительно через [движок](/apex/glossary#engine). В этом руководстве описаны регулярные операции и их фактические действия на хосте.

## Конфигурирование хоста {#configure}

Команда `apex configure` выполняет все шаги настройки в строгой последовательности. Если изменился только один слой, нужный шаг можно вызвать отдельно:

| Шаг | Эффект |
|---|---|
| `configure/base` | Устанавливает недостающие пакеты Debian после проверки плана APT на обновления и удаления, запускает rsyslog и проверяет закреплённую версию `/usr/local/bin/ufw-docker` перед запуском от root. Не запускайте другие пакетные операции одновременно. |
| `configure/timezone` | Применяет `configs/timezone`, если файл есть, и перезапускает активную службу cron после смены часового пояса. Поддерживает `--dry-run`. |
| `configure/ufw` | Применяет правила хоста, настраивает цепочки правил ядра и пробрасывает правила для контейнеров через `ufw-docker`. Поддерживает флаг `--dry-run`. |
| `configure/crowdsec` | Устанавливает CrowdSec (если он ещё не поставлен), копирует `configs/crowdsec/` в `/etc/crowdsec/`, ставит коллекции и firewall bouncer (если включён в настройках). Поддерживает флаг `--dry-run`. |
| `configure/cron` | Рендерит `configs/cron/crontab` через шаблонизатор и устанавливает расписание. Предусмотрены предпросмотр, аварийная остановка при пустом результате (код выхода 65) и откат при ошибке установки. Поддерживает флаг `--dry-run`. |
| `configure/systemd` | Рендерит файлы первого уровня из `configs/systemd/` в `/etc/systemd/system/`, перезагружает конфигурацию systemd (daemon-reload) и активирует каждый юнит `.service`. Поддерживает флаг `--dry-run`. |
| `configure/routing` | Включает пересылку IP-пакетов (forwarding), задаёт правило и таблицу маршрутизации (policy-routing) по метке fwmark для границы анклава. Шаг идемпотентен. |

После `configure/ufw` обязательно перезапустите службу: `sudo systemctl restart ufw`. Действие выведет напоминание и проверит, что порт SSH остаётся открытым.

## Жизненный цикл композиции {#compose}

```bash
apex compose up            # сначала core, затем сервисы по алфавиту
apex compose down          # обратный порядок
apex compose restart
apex compose --dry-run up  # только напечатать команды
apex compose -p apex restart traefik
apex compose -p app up -d
```

Указывайте параметры APEX (`-p` и `--dry-run`) перед действием. Остальные аргументы
передаются Docker Compose для выбранного проекта. Файлы `.env` и `apex.env`
подключаются автоматически, если существуют. Формы `apex compose restart apex traefik`
и `apex compose up -d apex` сохраняются; если имя сервиса или значение параметра
совпадает с именем композиции, выбирайте цель через `-p`.

Замените `app` именем композиции из своего репозитория. После изменения
монтирования или конфигурации контейнера используйте `up -d` для нужной
композиции; `restart` сохраняет прежнюю конфигурацию контейнера.

### Прямой запуск Compose для core

```bash
apex env --sync
cd compositions/apex
docker compose config --quiet
docker compose restart traefik
```

Синхронизация сохраняет текст секретов и UID/GID в `.env`, а также ссылку
на файл в хранилище tier. Управляемый блок содержит настройки `apex.env`, включая
профили, затем вычисленные значения узла и путей. Файл записывается с правами
`0600`. Повторите синхронизацию после изменения настроек или путей; не редактируйте
управляемый блок вручную. Переменные оболочки сохраняют приоритет Docker Compose.

`eval "$(apex env)"`, `apex env --dotenv` и `apex env --write generated.env`
выводят или записывают только вычисленные значения APEX. Они не загружают секреты
композиции и не заменяют `--sync`. Выбирайте один режим вывода за вызов.

## Резервные копии {#backups}

```bash
apex backup/run "$(cat <path-to-telegram-url-file>)"
```

Команда запускает [resticontainer](https://github.com/deytenit/resticontainer) в режиме one-shot под профилем compose `manual`. Процесс проходит следующие этапы:

1. Инициализирует репозиторий (если он ещё не создан).
2. Считывает compose-метки `restic.*` (`restic.enable`, `restic.backup.paths` и т. д.), чтобы определить, какие сервисы и пути нужно сохранять.
3. Создаёт единый снимок restic для всех выбранных путей хоста (`--host` = `APEX_NODE_HOST`, `--compression max`).
4. Применяет политику хранения (`forget --prune`) и отправляет уведомление.

Если ни один сервис с меткой `restic.*` не сформировал нового снимка, действие завершается с ошибкой. Полный процесс описан в разделе [Concept: Tiered storage](/apex/concepts/tiered-storage#backups). Чтобы резервное копирование и отправка отчётов в Telegram выполнялись автономно, добавьте команду в `configs/cron/crontab`.

## Синхронизация репозитория (capture-up) {#sync}

```bash
apex sync/repository <telegram-bot-url>
```

Действие фиксирует изменения рабочей копии в ветке `sync/<node>`, выполняет rebase на `origin/main` и отправляет ветку через force-push с lease. Этот механизм (capture-up) сохраняет актуальное состояние узла в репозиторий.

Действие прерывается с подробным сообщением, если подмодуль commons содержит незакоммиченные изменения или каталог `compositions/` отсутствует. При конфликтах rebase выполнение останавливается для ручного вмешательства. Подробнее архитектурная модель описана в разделе [Concept: Framework architecture](/apex/concepts/architecture#capture-up).

## Мониторинг обновлений {#updates}

```bash
apex sync/packages <telegram-bot-url>
```

Формирует единую сводку в Telegram о доступных обновлениях пакетов apt и устаревших образах контейнеров (локальные дайджесты сравниваются с реестром через `skopeo`). Действие ничего не меняет на хосте — это исключительно плановая проверка.

## Извлечение сертификатов {#certs}

```bash
apex utils/extract-traefik-certs <acme.json> <dest-dir> [telegram-bot-url]
```

Экспортирует сертификаты из ACME-хранилища граничного прокси в пары `fullchain.pem` и `privkey.pem` для каждого домена (с помощью утилиты в контейнере). Скрипт ограничивает права доступа к ключам до `600` и передаёт владение файлами запустившему пользователю. Это нужно сервисам, которым требуются исходные PEM-файлы вместо готового TLS-соединения от прокси.

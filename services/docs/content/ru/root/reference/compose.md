Действие `compose` предоставляет стандартизированную высокоуровневую точку входа для оркестрации файлов Docker Compose для всех проектов в рамках определенного узла.

## Основная операция Compose {#actions}

| Операция | Описание |
| :--- | :--- |
| `compose <node> <action>` | Выполняет заданную команду Docker Compose (например, `up`, `down`, `restart`) по всей инфраструктуре узла. |

## Порядок оркестрации {#order}

Для поддержания правильных зависимостей (особенно при завершении работы или запуске прокси-серверов и сетей уровня инфраструктуры), действие `compose` интеллектуально упорядочивает выполнение:

### Запуск (`up`, `restart`)
При запуске или перезапуске сервисов действие использует **Прямой порядок** (Forward Order):
1. **Инфраструктура узла (Node Infra)**: Сначала обрабатывается файл `docker-compose.yml` уровня узла (находится в корне директории узла).
2. **Корневая инфраструктура (Root Infra)**: Затем обрабатывается проект `root/docker-compose.yml`, если он существует (обычно содержит Traefik, Socket Proxy и т.д.).
3. **Проекты**: Наконец, в алфавитном порядке обрабатываются все остальные директории проектов.

### Остановка (`down`)
При остановке сервисов действие использует **Обратный порядок** (Reverse Order), чтобы проекты корректно отключились до того, как упадет сеть или прокси:
1. **Проекты**: Все стандартные проекты останавливаются в обратном алфавитном порядке.
2. **Корневая инфраструктура (Root Infra)**: Проект `root/docker-compose.yml` останавливается.
3. **Инфраструктура узла (Node Infra)**: В самом конце отключается `docker-compose.yml` уровня узла.

## Опции {#options}

Вы можете передавать стандартные аргументы Docker Compose в конец команды.
Кроме того, действие поддерживает режим пробного запуска (dry-run):

- `--dry-run`: Выводит команды, которые будут выполнены, без их фактического запуска.

**Пример использования:**
```bash
root compose daedalus up -d --remove-orphans
root compose daedalus restart --dry-run
root compose daedalus down
```

**Цель:** Настроить, развернуть и мониторить экземпляр бота Quetza.

## 1. Подготовка окружения

Quetza полагается на переменные окружения для конфигурации. **Никогда** не сохраняйте их в систему контроля версий.

| Переменная | Описание | Обязательно |
| :--- | :--- | :--- |
| `DISCORD_TOKEN` | Токен бота из Discord Developer Portal | **Да** |
| `CLIENT_ID` | ID приложения для регистрации slash-команд | **Да** |
| `LLAMA_API_KEY` | Требуется при использовании модуля ИИ | Нет |

## 2. Стратегии развертывания

{{< tabs >}}
{{< tab name="Docker (Рекомендуется)" >}}
**Docker** обеспечивает стабильное окружение выполнения.

1.  **Сборка** образа:

    ```bash
    docker build -t quetza-bot .
    ```

2.  **Запуск** контейнера:
    ```bash
    docker run -d \
      --env-file .env \
      --name quetza \
      quetza-bot
    ```
{{< /tab >}}
{{< tab name="Из исходников (Source)" >}}
Развертывание **из исходников** полезно для разработки.

1.  **Установка** зависимостей:

    ```bash
    pnpm install
    ```

2.  **Сборка** проекта:

    ```bash
    pnpm build
    ```

3.  **Запуск** бота:
    ```bash
    pnpm start
    ```
{{< /tab >}}
{{< /tabs >}}

## 3. Операционный мониторинг

После запуска используйте следующие механизмы для проверки работоспособности:

- **Логи:** Проверьте стандартный вывод (логи Docker) на наличие ошибок инициализации.
- **Команда `/ping`:** Проверяет задержку сети и отзывчивость API.
- **Команда `/modules`:** Перечисляет все загруженные модули, чтобы подтвердить доступность функций.

> [!WARNING]
> **Ограничение масштабирования:**
> Quetza следует модели "один экземпляр на один токен". Не запускайте несколько экземпляров с одним и тем же токеном, так как это вызовет конфликты WebSocket.

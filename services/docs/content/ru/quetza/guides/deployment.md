**Цель:** настроить, развернуть и контролировать работу бота Quetza.

## 1. Подготовка окружения

Quetza настраивается через переменные окружения. **Никогда** не сохраняйте их в систему контроля версий.

| Переменная | Описание | Обязательно |
| :--- | :--- | :--- |
| `DISCORD_TOKEN` | Токен бота из Discord Developer Portal | **Да** |
| `CLIENT_ID` | Идентификатор приложения для регистрации слэш-команд | **Да** |
| `LLAMA_API_KEY` | Требуется для модуля ИИ | Нет |

## 2. Способы развёртывания

{{< tabs >}}
{{< tab name="Docker (рекомендуется)" >}}
**Docker** обеспечивает предсказуемое и изолированное окружение.

1.  **Сборка** образа:

    ```bash
    docker build -t quetza-bot .
    ```

2.  **Запуск** контейнера:
    ```bash
    docker run -d \
      --env-file .env \
      --name quetza \
      quetza-bot
    ```
{{< /tab >}}
{{< tab name="Из исходного кода" >}}
Развёртывание **из исходного кода** подходит для разработки и отладки.

1.  **Установка** зависимостей:

    ```bash
    pnpm install
    ```

2.  **Сборка** проекта:

    ```bash
    pnpm build
    ```

3.  **Запуск** бота:
    ```bash
    pnpm start
    ```
{{< /tab >}}
{{< /tabs >}}

## 3. Мониторинг

После запуска проверьте состояние бота:

- **Логи:** проверьте стандартный вывод (логи Docker) на ошибки инициализации.
- **Команда `/ping`:** измеряет задержку сети и отзывчивость API.
- **Команда `/modules`:** выводит список загруженных модулей, подтверждая доступность функций.

> [!WARNING]
> **Ограничение масштабирования:**
> Quetza работает по модели «один экземпляр на один токен». Не запускайте несколько копий бота с одним токеном: это вызовет конфликты соединений WebSocket.
